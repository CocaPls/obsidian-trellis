# Trellis

[English](README.md) | **한국어**

[![CI](https://github.com/CocaPls/obsidian-trellis/actions/workflows/ci.yml/badge.svg)](https://github.com/CocaPls/obsidian-trellis/actions/workflows/ci.yml)
· [커뮤니티 플러그인 페이지](https://community.obsidian.md/plugins/trellis)

Trellis는 계층형 **관리 태그**를 등록하고 필요한 태그를 노트의 **파일명 슬롯**에
반영합니다. 파일명 동기화가 켜져 있으면 태그 트리에서 노트를 옮길 때 Obsidian의
링크 안전 이름변경을 통해 파일명이 따라옵니다.

```text
태그  #projects/PRJ/01/DOC/01  →  파일  PRJ01DOC01-회의록.md
태그  #projects/PRJ/01/DOC/02  →  파일  PRJ01DOC02-회의록.md  (자동)
```

![사이드바 트리 뷰](screenshots/tree-view.png)

## 왜 Trellis인가

제 볼트는 노트가 어디에 속하는지 짧은 파일명 코드로 표시합니다. 이 코드를 손으로
관리하는 일은 번거롭고 틀리기 쉬웠기에 Trellis가 하나의 위치 태그에서 코드를
만들게 했습니다. 사람은 파일명을 빠르게 훑을 수 있고 CLI·AI 도구는 정확한 노트를
지정할 수 있습니다.

## 작동 방식

`PRJ01DOC01-회의록.md`를 예로 들면:

- `PRJ01DOC01`은 `#projects/PRJ/01/DOC/01`에서 만든 관리 대상
  **파일명 코드**입니다.
- `-`는 코드와 제목 사이의 설정 가능한 경계 기호입니다.
- `회의록`은 사용자의 자유 **제목**이며 Trellis가 다시 쓰지 않습니다.

태그가 원본입니다. 태그를 바꾸면 코드가 따라오고, 관리 코드를 손으로 고치면 다음
동기화 때 태그 기준으로 복원됩니다.

## 핵심 기능

- **일시정지 가능한 파일명 동기화** — 다시 켜기 전 정확한 차이를 보여주며 중복과
  파일명 충돌을 차단합니다.
- **사이드바 트리** — 폴더 대신 태그로 트리를 만들고 노트/태그 모드, 새 노트,
  현재 노트 찾기, 전체 접기·펼치기, 분기 표시 제어와 태그별 색상을 제공합니다.
- **하위 위치 함께 변경** — 한 위치와 모든 하위를 미리 본 뒤 태그·파일명·
  위키링크를 함께 옮기며 실패 시 롤백하고 완료 뒤 되돌릴 수 있습니다.
- **기존 파일명 편입** — 볼트·폴더·개별 노트 범위를 골라 파일명 코드에서 태그를
  만들고, 드라이런·진행 제어·되돌리기를 제공합니다.
- **안전한 파일명 구조** — 필요한 만큼의 태그/이름 슬롯, 사이 공백, 휴대 가능한
  사용자 지정 기호, 계층 표시와 슬롯 감싸기를 설정합니다.
- **관리 태그 등록부와 현황** — 파일명 반영과 독립적으로 검색·복원 가능한 보관,
  사이드바 전용 태그, 사용 조합, 파일명 차이와 충돌을 확인합니다.
- **한국어·영어 UI** — 기본적으로 Obsidian의 언어를 따릅니다.

## 설치

**Obsidian에서:** 설정 → 커뮤니티 플러그인 → 탐색에서 *Trellis*를 검색한 뒤
설치하고 활성화합니다.

**수동으로:** [최신 릴리스](https://github.com/CocaPls/obsidian-trellis/releases/latest)에서
`main.js`, `manifest.json`, `styles.css`를 받아
`내-볼트/.obsidian/plugins/trellis/`에 넣고 플러그인을 활성화합니다.

## 빠른 시작

1. 프론트매터에 `tags: [projects/PRJ/01/DOC/01]`처럼 위치 태그를 추가합니다.
2. Trellis가 파일명 코드를 `PRJ01DOC01`로 동기화합니다.
3. 리본에서 트리를 열고 계층을 탐색합니다.
4. **하위 위치 함께 변경**으로 하위 트리 전체를 옮깁니다.
5. 코드가 이미 있는 노트는 **기존 파일명 편입**으로 태그를 만듭니다.
6. 일괄 작업은 적용 전 미리보기를 확인합니다. 지원되는 완료 작업은 되돌리기
   기록을 남깁니다.

설정한 네임스페이스는 즉시 활성화됩니다. 다른 용도로 쓰는 태그와 겹치지 않는
네임스페이스를 사용하세요. 그 아래의 모든 하위 태그는 의도적으로 관리 위치로
취급됩니다.

## 유연한 파일명 구조

단일 코드 경로가 기본이지만 별도 고급 모드 없이 같은 단계형 편집기에서 여러
선택적 태그 슬롯도 구성할 수 있습니다.

- **복수 태그 슬롯** — 여러 관리 태그와 하나의 자유 제목을 결합합니다.

  ```text
  #projects/PRJ/01 + #areas/ENG/02  →  PRJ01-project-overview--ENG02
  ```

  태그 슬롯마다 등록 태그 원천, 계층 표시와 감싸기를 따로 정합니다. 구조 변경은
  반드시 미리보기를 거치며 모호하거나 충돌하는 구성은 거부됩니다. 이름 슬롯은
  생략할 수 있습니다. 전역 구조가 `[A]-[B]-[C]`여도 노트마다 필요한 태그만 넣어
  `A`, `A-B`, `A-C`, `B-C`를 함께 운용할 수 있으며, 빈 슬롯과 그
  구분자는 자동으로 접힙니다. 이름 슬롯을 제거할 때는 사람용 이름 손실을 별도로
  경고하고, 같은 최종 파일명이 생기면 구조 변경을 차단합니다.
- **루트 네임스페이스** — 모든 관리 태그를 `#work/projects/...` 같은 공통 루트
  아래에 두되 그 루트를 파일명에는 넣지 않습니다. 확인 뒤 마이그레이션하고
  되돌릴 수 있습니다.
- **태그 값 제안** — 트리에서 노트를 만들 때 설정한 순번, 날짜, 로컬/UTC
  타임스탬프, 알파벳/숫자 교대 형식을 제안합니다.

파일명 동기화·중첩 태그 트리·하위 위치 변경은 등록된 모든 트렐리 태그를
인식합니다. 각 정의는 파일명 반영, 사이드바 전용, 사이드바 숨김으로 운용할 수
있습니다. 노트 전용 트리는 축으로 쓸 표시 태그 하나를 고릅니다. 검토한 하위
분기를 다른 정의로 옮겨 계층을 분리하거나 편입할 수도 있습니다. 파일명 구성에서
뺀 정의는 보관할 수 있습니다. 기존 태그는 정리할 수 있도록 계속 인식하지만,
복원하기 전까지 활성 선택 목록과 사이드바에서는 제외합니다. 기존 파일명 편입은
태그 없이 여러 슬롯으로 된 파일명을 항상 역산할 수 없으므로 첫 번째 바깥쪽 코드를
계속 사용합니다.

## 설정

![설정 탭](screenshots/settings.png)

설정은 일반 동작과 파일명·태그의 두 영역으로 나뉩니다. 파일명·태그 영역은 검색
가능한 관리 태그 목록, 가로 슬롯 순서와 선택 항목 하나의 편집기를 함께 제공합니다.
파일명 동기화, 속성의 축약 태그 표시, 정의별 현황·사용 조합·파일명 차이와 충돌도
여기서 다룹니다.

볼트 전체에 영향을 주는 설정은 먼저 대기 상태로 둡니다. Trellis는 정확한 대상
파일을 보여주고 충돌과 해석 모호성을 검사한 뒤 Obsidian의 이름변경 API로
적용합니다. 취소하거나 실패하면 트랜잭션을 롤백합니다.

## AI·스크립트 자동화

Trellis는 이미 Obsidian 안에서 실행되는 도구를 위해 실험적인 프로세스 내부
`describe / inspectNote → planChange → applyChange` 표면을 제공합니다. 네트워크, REST, URI,
MCP endpoint는 열지 않으며, 검사 뒤 노트나 파일명 구조가 바뀌면 적용을 거부합니다.

예제·결과 구조·안전 경계는 [보호된 자동화](docs/automation.ko.md)를 참고하세요.

## 호환성·개인정보·안전

Obsidian **1.8.7** 이상이 필요합니다. 데스크톱·모바일 모두 지원합니다.

Trellis는 Obsidian의 공개 볼트 API를 통해 로컬에서만 작동합니다. 네트워크 요청,
텔레메트리, 광고, 계정 요구가 없으며 현재 볼트 밖의 파일에 접근하지 않습니다.

파일명과 태그의 일괄 변경은 많은 노트에 영향을 줄 수 있습니다. 미리보기를
확인하고 다른 일괄 편집 도구와 마찬가지로 일반적인 볼트 백업을 유지하세요.
