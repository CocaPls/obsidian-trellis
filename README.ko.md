# TRELLIS

[English](README.md) | **한국어**

[Obsidian](https://obsidian.md)용 태그 기반 파일명 동기화 플러그인. 계층형 **위치
태그**를 유일한 진실원(source of truth)으로 두면, TRELLIS가 그 태그를 **파일명
접두사**(*tagkey*)로 자동 반영합니다 — 링크는 깨지지 않습니다.

태그 트리에서 노트를 옮기면 파일명 접두사가 따라옵니다. 수동 일괄 이름변경도,
깨진 위키링크도 없습니다.

```
노트에 태그    #trel/S88/B07     →  파일명  S88B07-meeting-notes.md
태그 변경      #trel/S88/B99     →  파일명  S88B99-meeting-notes.md   (자동)
```

![사이드바 트리 뷰](screenshots/tree-view.png)

## 🧩 작동 방식

TRELLIS는 파일명을 세 부분으로 읽습니다 — 예: `S88B07-meeting-notes.md`

- **`S88B07`** — **태그키**: 노트의 위치 태그에서 만들어지는 식별자
  (`#trel/S88/B07` → `S88B07`). TRELLIS가 다루는 유일한 부분입니다.
- **`-`** — 태그키와 이름 사이의 **구분자** (기본 `-`).
- **`meeting-notes`** — **네임키**: 사용자가 붙인 제목. TRELLIS는 건드리지 않습니다.

태그가 진실원입니다 — 태그를 바꾸면 태그키가 그에 맞게 다시 쓰이고, 태그키를
손으로 바꾸면 태그 기준으로 복원됩니다.

## ✨ 기능

- **단방향 동기화** — 노트의 위치 태그가 바뀌면 파일명 접두사가 그에 맞게
  다시 쓰입니다. 옵시디언의 링크 안전 rename API를 거치므로 위키링크가 자동
  갱신됩니다. 파일명이나 제목을 손으로 바꿔도 태그 기준으로 복원됩니다. 태그가
  항상 진실원입니다. 위치 태그는 frontmatter에 두세요 — cascade와 bootstrap이
  읽고 다시 쓰는 대상입니다. 노트 하나 = 위치 태그 하나(그 이상은 알림으로
  표시).
- **Cascade 이름변경** — 태그 하나를 바꾸면 그 하위 전체가 따라옵니다. 상위
  계층을 새로 끼워 넣는 변경도 처리합니다. 파일명·위키링크가 함께 따라옵니다.
- **사이드바 트리 뷰** — 위치 태그 계층을 접고 펼 수 있는 폴더 같은 트리로
  보여줍니다(폴더 구조가 아니라 태그로 구성).
- **Bootstrap** — 파일명 접두사는 있지만 아직 태그가 없는 기존 볼트를
  온보딩합니다. 체크박스 트리로 범위를 고르고(볼트 전체·폴더·개별 노트, 드래그로
  훑어 선택, 검색, 태그 없는 노트만 보기), 드라이런으로 미리 보고, 진행률을
  지켜보며(일시정지·재개·중단), 한 번에 되돌릴 수 있습니다. 파일별 오류가 격리되어 노트 하나가
  전체를 멈추지 않습니다. Bootstrap은 접두사를 글자↔숫자 경계에서 태그
  세그먼트로 쪼갭니다(`S88B07` → `S/88/B/07`, `PROJ123` → `PROJ/123`) — 특정
  명명 체계에 매이지 않습니다. 그런 경계가 없거나 태그가 담을 수 없는 문자가
  든 접두사는 건너뛰며 드라이런에 표시됩니다.
- **중복 위치 태그 정리** — 노트가 같은 네임스페이스의 위치 태그를 둘 이상
  가지면 TRELLIS가 이를 표시하고 정리 명령을 제공합니다. 남길 태그를 고르면
  나머지는 제거됩니다. 대량 볼트를 위해 배치 처리되며 되돌리기를 지원합니다.
- **구분자 일괄 변경** — 설정에서 구분자를 바꾸면 볼트 전체에서 tagkey 경계
  구분자만 교체됩니다(제목 안의 같은 기호는 보존). 되돌리기 지원.
- **다국어(i18n)** — 옵시디언 언어에 맞춰 한국어/영어 UI 자동 전환.

## 📦 설치

**커뮤니티 플러그인:** 옵시디언에서 **설정 → 커뮤니티 플러그인 → 탐색**을 열고
**Trellis**를 검색해 설치·활성화합니다.

**수동:**

1. 최신 [릴리스](../../releases)에서 `main.js`·`manifest.json`·`styles.css`를
   받습니다.
2. 볼트의 `.obsidian/plugins/trellis/` 폴더에 넣습니다.
3. **설정 → 커뮤니티 플러그인**에서 활성화합니다.

## 🚀 사용법

1. **노트에 태그** — frontmatter에 위치 태그(예: `tags: [trel/S88/B07]`)를 넣으면
   파일명 접두사가 `S88B07`로 자동 동기화됩니다.
2. **계층 변경** — 명령 팔레트나 노트 우클릭에서 **"위치 태그 이름 변경
   (cascade)"** 실행 — 파일명·위키링크가 따라옵니다.
3. **트리 뷰** — 리본 아이콘으로 사이드바 트리를 엽니다.
4. **기존 볼트 온보딩** — **"Bootstrap"** 실행으로 파일명 접두사에서 태그를
   역산합니다(범위 선택 → 드라이런 → 적용).
5. **중복 정리** — **"중복 위치 태그 점검"** 실행으로 위치 태그가 둘 이상인
   노트를 찾아 남길 것을 고릅니다.
6. **구분자 변경** — 설정에서 바꾸면 확인 후 볼트 전체에 적용됩니다.

## 🧪 고급 — 멀티 키 체계 (experimental)

기본은 태그키 접두사 하나 + 자유 제목입니다. 노트에 **식별자가 둘 이상** 필요하면
(예: 프로젝트 코드 *와* 영역 코드) 설정에서 **고급 — 멀티 키 슬롯**을 켜서 파일명을
**슬롯**의 위치 배열로 정의할 수 있습니다:

- **태그키** 슬롯 하나 이상 — 각자 자기 태그 네임스페이스에서 동기화;
- **네임** 슬롯 하나 (자유 제목);
- 슬롯 사이마다 구분자 하나.

```
#trel/AA/01  +  #key2/BB/02      →   AA01-my-note--BB02
두 번째 태그 변경   #key2/BB/09    →   AA01-my-note--BB09   (자동)
```

**experimental·옵트인**입니다: 기본은 꺼져 있고, 검증된 단일키 엔진이 기본
경로로 남습니다. 멀티 키가 켜져 있어도 트리 뷰·bootstrap·cascade·구분자 일괄
변경은 여전히 **첫 번째 태그키 슬롯** 기준으로 동작합니다.

슬롯 편집기는 편집 내용을 **staged(대기)** 합니다: 슬롯을 추가·삭제하고 각
네임스페이스를 정해도 **[적용]**을 누르고 확인하기 전까지는 아무것도 바뀌지
않습니다 — 기존 파일은 태그가 바뀔 때 다시 동기화될 뿐, 그 자리에서 이름이
바뀌지 않습니다. 네임스페이스와 구분자는 입력 즉시 검증되어, 비어 있거나
중복이거나 잘못된 값은 볼트에 닿기 전에 걸러집니다.

## 📸 스크린샷

**Bootstrap — 온보딩 대상 고르기.** 이미 태그된 노트는 완료로 표시되고, 태그
없는 노트를 선택할 수 있습니다(볼트 전체·폴더·개별 노트).

![Bootstrap 대상 선택](screenshots/bootstrap.png)

**Cascade 이름변경 — 하위 전체 이동.** 태그 하나를 바꾸면 그 아래 모든 노트가
파일명·위키링크까지 따라옵니다.

![Cascade 이름변경](screenshots/cascade-rename.png)

**중복 정리 — 노트당 위치 하나.** 노트에 위치 태그가 둘 이상이면 남길 것을
고르고 나머지는 제거합니다(되돌리기 가능).

![중복 위치 태그 정리](screenshots/dedup.png)

## ⚙️ 설정

![설정 탭](screenshots/settings.png)

- **위치 태그 네임스페이스** — 어떤 태그를 진실원으로 볼지 (예: `trel`);
  입력 후 **[적용]** 버튼으로 커밋
- **구분자** — tagkey와 제목 사이 문자 (예: `-`); 입력 즉시 검증하고 확인 후 볼트 전체에 적용
- **키 위치** — 파일명의 접두(앞) 또는 접미(뒤)
- **고급 — 멀티 키 슬롯** — 기본 꺼짐; 멀티 키 체계용 슬롯 편집기 옵트인
  (experimental, 위 참고)
- **사이드바 트리 뷰** — 켬 / 끔
- **사이드바 뷰 이름** — 트리 뷰 탭의 사용자 지정 제목 (비우면 기본값)
- **트리 정렬** — tagkey / 수정 시간 / 생성 시간
- **사이드바 헤더 버튼** — 헤더의 각 동작 버튼을 개별로 켜고 끄기
- **언어** — 자동 / 한국어 / 영어
- **관리 노트** — 관리되는 위치 태그를 가진 노트 수와 활성 네임스페이스를
  읽기 전용으로 요약해, 설정이 제대로 됐는지 한눈에 확인

## 🧱 설계 (내부)

내부적으로 파일명은 **구분자**로 이어진 **슬롯**의 위치 배열입니다 — 기본은
2슬롯 `[태그 슬롯, 네임 슬롯]` 구성이라, 코어를 새로 쓰지 않고도 멀티 키로
확장할 수 있습니다. 변환 로직은 `tagkey.ts`(순수 함수·유닛 테스트)에 있고,
`main.ts`는 옵시디언 연결부입니다. live sync는 형식 무관(format-agnostic) —
태그 경로가 무엇이든 그대로 반영하므로 어떤 체계든 작동합니다. (역방향인 bootstrap은 평면
접두사를 글자/숫자 경계에서 쪼갭니다 — 체계에 두루 일반적이나, 같은 문자
종류가 이어진 구간 내부의 경계는 복원하지 못합니다.)

## 💡 왜 만들었나

제 볼트는 파일명의 짧은 ID 접두사에 크게 기댑니다 — 각 노트가 자기 위치를
나타내는 코드를 답니다. 이 접두사를 손으로 맞추는 건 번거롭고 실수가 잦아서,
TRELLIS가 위치 태그로 그걸 몰아줍니다: 노트에 태그를 달면 파일명 접두사가 링크
안전하게 따라옵니다. 안정적이고 예측 가능한 접두사 덕에 볼트를 훑어보기 쉽고,
CLI AI 도구에게 ID로 정확한 파일·폴더를 지목할 수 있습니다.

태그가 유일한 진실원이고, 파일명(과 위키링크)은 알아서 따라옵니다.
