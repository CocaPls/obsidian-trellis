# Trellis

[English](README.md) | **한국어**

Trellis는 계층형 관리 태그를 이용해 여러 노트의 파일명 일부를 일관되게
관리합니다. 태그가 진실원이며, 이름 변경은 Obsidian을 통해 실행되므로 파일과 함께
내부 링크도 갱신될 수 있습니다.

```text
태그     #projects/PRJ/01/DOC/01
파일명   PRJ01DOC01-회의록.md

태그     #projects/PRJ/01/DOC/02
파일명   PRJ01DOC02-회의록.md
```

모든 노트에 관리 태그를 요구하지 않습니다. 등록한 네임스페이스 밖의 노트는 기존
태그와 파일명을 그대로 유지합니다.

## 왜 Trellis를 쓰나요?

규칙적인 파일명 접두사는 큰 볼트를 훑어보기 쉽게 하지만, 여러 노트에서 같은
구조를 손으로 유지하면 번거롭고 실수하기 쉽습니다. Trellis는 파일명 구조를 한 번
정하고 프론트매터 태그에서 반복해서 계산합니다.

```text
프론트매터 태그 → 파일명 구조 → Obsidian 이름 변경 → 내부 링크 갱신
```

구조화된 파일명 부분은 일관되게 유지하면서, 선택적인 사람용 제목은 사용자가 직접
편집할 수 있습니다.

## 핵심 모델

- **관리 태그** — `#projects/...`, `#areas/...`처럼 Trellis에 등록한 계층형 태그
  네임스페이스입니다.
- **태그 슬롯** — 관리 태그 하나에서 계산해 파일명에 투영하는 자리입니다.
- **일반 슬롯** — 파일명에서 사용자가 자유롭게 관리하는 선택적 제목입니다. 한
  구조에는 일반 슬롯을 최대 하나 둘 수 있습니다.
- **경계** — 값이 있는 슬롯 사이를 잇는 기호, 공백 한 칸 또는 붙임입니다.
- **파일명 구조** — 관리 노트에 공통으로 적용하는 슬롯과 경계의 순서입니다.

관리 태그 등록과 파일명 투영은 서로 독립적입니다. 어떤 관리 태그는 파일명에 넣지
않고 Trellis 사이드바에만 보이게 할 수 있으며, 정의별로 표시·숨김·보관을 정할 수
있습니다.

## 파일명 구조

기본 구조는 태그 슬롯 하나와 일반 슬롯 하나입니다.

```text
[projects 태그] - [일반 제목]
PRJ01DOC01-회의록
```

선택적인 태그 슬롯을 여러 개 조합할 수도 있습니다.

```text
#projects/PRJ/01 + #areas/ENG/02
→ PRJ01-프로젝트개요-ENG02
```

각 노트에는 필요한 관리 태그만 넣으면 됩니다. 값이 없는 슬롯과 사용되지 않는
경계는 자동으로 사라집니다.

태그 슬롯마다 다음을 설정할 수 있습니다.

- 원본으로 사용할 관리 태그 정의
- 계층 표시 방식: 숨김, 기본 기호 또는 안전한 사용자 지정 문장부호
- 감싸기 없음, 둥근 괄호 또는 안전한 사용자 지정 감싸기
- 언더바를 유지할지, 파일명에서만 공백으로 표시할지

언더바 변환은 파일명에 투영되는 글자만 바꿉니다.

```text
저장된 태그     #topics/design_system
파일명 표시     design system
```

각 슬롯 경계에는 다음을 사용할 수 있습니다.

- 좌우 공백을 선택할 수 있는 기호
- 공백 한 칸
- 구분자 없이 붙이기

Trellis는 안전하게 다시 해석할 수 없거나, 같은 파일명을 만들거나, 지원 환경에서
안전하지 않은 문자를 사용하는 구조를 거부합니다.

## 주요 기능

- **단방향 파일명 동기화** — 프론트매터 관리 태그가 파일명 슬롯을 바꿉니다.
  파일명에 투영된 부분을 편집해도 태그를 역으로 고치지는 않습니다.
- **일시정지와 검토** — 파일명 동기화를 끈 채 태그를 편집하고, 다시 켜기 전에
  정확한 차이와 충돌을 검토할 수 있습니다.
- **태그 트리 사이드바** — 관리 계층 탐색, 노트 열기·생성, 현재 노트 찾기, 정렬,
  가지 전체 펴기·접기를 제공합니다.
- **복수 사이드바 표시** — 여러 관리 태그 정의를 함께 표시하고, 정의나 특정 분기를
  선택해서 숨길 수 있습니다.
- **하위 태그 함께 변경** — 관리 태그와 모든 자손의 변경을 미리 본 뒤 같은 정의
  안이나 다른 정의로 옮길 수 있습니다.
- **기존 파일명 편입** — 호환되는 파일명에서 관리 태그 후보를 만들고 드라이런 뒤
  선택한 범위에만 적용합니다.
- **중복 정리** — 파일명에 쓰이는 한 관리 정의의 값이 노트에 여러 개 있을 때 남길
  값을 검토합니다.
- **태그값 제안** — 새 노트 생성 시 순번, 날짜, 타임스탬프, 알파벳·숫자 교대
  형식을 선택적으로 제안합니다.
- **속성 태그 표시** — 저장된 태그를 바꾸지 않고 Obsidian 속성 화면의 관리 태그
  라벨을 짧게 표시할 수 있습니다.
- **볼트 현황** — 정의별 사용량, 조합, 인라인 태그 경고, 파일명 차이와 정확한
  충돌을 확인합니다.

## 안전한 쓰기와 완료 확인

Trellis는 태그와 파일명 변경을 관리되는 쓰기 작업으로 처리합니다.

- 실시간 동기화, 자동화, 일괄 작업은 하나의 쓰기 소유권을 공유합니다.
- 같은 노트에서 연달아 발생한 메타데이터 이벤트를 모아 최종 상태로 한 번
  계산합니다.
- 일괄 변경은 적용 전에 대상 노트를 보여주고, 지원되는 작업은 되돌리기 기록을
  남깁니다.
- 모든 이름 변경은 같은 휴대성·충돌·재진입·링크 안전 검사를 거칩니다.
- 실패하거나 취소된 일괄 작업은 명령의 성격에 따라 앞선 변경을 되돌리거나 정확한
  실행취소 기록을 남기며, 확인이 필요한 나머지를 보고합니다.
- Obsidian이 종료될 때 진행 중이던 작업은 다음 실행에서 완료로 오인하지 않고
  중단 상태로 알립니다.

이름 변경은 Obsidian 파일 관리자를 사용하며 Obsidian의 **내부 링크 자동 업데이트**
설정을 따릅니다.

## 빠른 시작

1. Trellis를 설치하고 활성화합니다.
2. **설정 → Trellis → 파일명·태그**를 엽니다.
3. `projects` 같은 관리 태그 네임스페이스를 등록합니다.
4. 그 관리 태그를 파일명 구조의 태그 슬롯에 연결합니다.
5. 노트 프론트매터에 `projects/PRJ/01/DOC/01` 같은 태그를 넣습니다.
6. 볼트 전체에 영향을 주는 변경은 적용 전에 미리보기를 확인합니다.

프론트매터 예시:

```yaml
---
tags:
  - projects/PRJ/01/DOC/01
---
```

프론트매터 태그만 관리 진실원으로 사용합니다. 인라인 태그는 수정하지 않으며 관리
네임스페이스와 겹치면 별도 경고로 표시합니다.

## 도구와 AI를 위한 자동화

Trellis는 이미 Obsidian 안에서 실행되는 도구를 위해 보호된 프로세스 내부 표면을
제공합니다.

```text
describe / inspectNote → planChange → applyChange → awaitIdle
```

검사 뒤 노트, 태그, 파일명 구조 또는 대상 경로가 바뀌면 계획 적용을 거부합니다.
호출자는 작업 상태를 확인할 수 있으며, Trellis가 유휴 상태여도 확인 필요 보고가
남아 있으면 작업을 끝난 것으로 간주하면 안 됩니다.

Trellis는 네트워크, REST, URI 또는 MCP endpoint를 열지 않습니다. 요청·응답 계약은
[보호된 자동화](docs/automation.ko.md)를 참고하세요.

## 현재 책임 경계

- 현재 파일명 원본으로 사용하는 속성은 프론트매터 `tags`입니다.
- 파일명에 투영하는 각 관리 정의는 노트마다 단일값으로 취급합니다.
- 한 파일명 구조에는 태그 슬롯 여러 개와 자유 일반 슬롯 최대 하나를 둘 수
  있습니다.
- Trellis는 노트 파일을 바꾸며, 동명 폴더나 Folder Note 쌍을 함께 바꾸지 않습니다.
- 다중값 분류, 노트 의미, 폴더 구성, Git 이력, 식별자 부여 규칙은 사용자가
  결정합니다.

이 경계는 특정한 지식관리 체계를 강제하지 않고 서로 다른 볼트에서 Trellis를 쓸 수
있게 합니다.

## 설치

### 커뮤니티 플러그인

Obsidian에서 **설정 → 커뮤니티 플러그인 → 탐색**을 열고 **Trellis**를 검색한 뒤
설치하고 활성화합니다.

### 수동 설치

[GitHub 릴리스](https://github.com/CocaPls/obsidian-trellis/releases)에서 같은 버전의
`main.js`, `manifest.json`, `styles.css`를 받아 다음 폴더에 넣습니다.

```text
내-볼트/.obsidian/plugins/trellis/
```

그다음 Obsidian의 커뮤니티 플러그인 설정에서 Trellis를 활성화합니다.

## 호환성·개인정보·안전

- Obsidian 1.8.7 이상이 필요합니다.
- 데스크톱과 모바일을 지원합니다.
- Obsidian 공개 API를 통해 로컬에서만 작동합니다.
- 네트워크 요청과 텔레메트리가 없습니다.
- 현재 볼트 밖의 파일에 접근하지 않습니다.

파일명과 태그 마이그레이션은 많은 노트에 영향을 줄 수 있습니다. 큰 변경 전에는
미리보기를 확인하고 일반적인 볼트 백업을 유지하세요.

## 개발

```bash
npm ci
npm run lint
npm run build
npm test
```

순수 파일명 구조 로직은 `src/tagkey.ts`, 저장 설정과 작업 추적은
`src/settings-model.ts`와 `src/operation-state.ts`, Obsidian 연결은 `src/main.ts`에
있습니다.

개발과 릴리스 절차는 [CONTRIBUTING.md](CONTRIBUTING.md)를 참고하세요.
