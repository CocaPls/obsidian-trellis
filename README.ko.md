# Trellis

[English](README.md) | **한국어**

Trellis는 노트의 계층형 **위치 태그**를 원본(source of truth)으로 삼아, 그 값을
노트의 **파일명 접두어**에 자동으로 반영합니다. 링크는 깨지지 않습니다.

태그 트리에서 노트를 옮기면 파일명 접두어가 따라옵니다. 손으로 일괄 이름을
바꿀 필요도, 위키링크가 깨질 일도 없습니다.

```
#trel/S88/B07 태그    →  파일명  S88B07-회의록.md
#trel/S88/B99 로 변경  →  파일명  S88B99-회의록.md   (자동)
```

![사이드바 트리 뷰](screenshots/tree-view.png)

## 작동 방식

Trellis는 파일명을 세 부분으로 읽습니다. `S88B07-회의록.md`라면:

- `S88B07` = **태그키(tagkey)** — 위치 태그로 만든 접두어(`#trel/S88/B07` →
  `S88B07`). Trellis가 손대는 건 이 부분뿐입니다.
- `-` = 태그키와 제목 사이의 **구분자**(기본값 `-`).
- `회의록` = 여러분의 **제목**. Trellis는 여기엔 손대지 않습니다.

태그가 원본입니다. 태그를 바꾸면 태그키가 그에 맞게 다시 쓰이고, 태그키를
손으로 고쳐도 다음 동기화 때 태그 기준으로 복원됩니다.

## 무엇을 하나

- **파일명 동기화.** 위치 태그가 바뀌면 파일명 접두어가 그에 맞게 다시
  쓰입니다. Obsidian의 링크 안전 rename을 거치므로 위키링크는 알아서
  갱신됩니다. 위치 태그는 프론트매터에 둡니다. 노트 하나에 위치 태그는 하나이며,
  두 개가 붙으면 Trellis가 알려줍니다.
- **연쇄 이름변경(cascade).** 태그 하나를 바꾸면 그 아래 하위 트리 전체가
  따라옵니다. 중간에 새 상위 단계를 끼워 넣을 수도 있습니다. 파일명과 위키링크가
  함께 움직입니다.
- **사이드바 트리.** 폴더가 아니라 위치 태그로 만든, 접었다 펼 수 있는
  폴더식 트리로 노트를 봅니다. 두 가지 모드가 있습니다 — *노트*(기본값. 태그
  아래 여러분의 노트)와 *태그*(태그 계층 자체. 네임스페이스를 훑어보며 거기서
  노트를 열 수 있습니다).
- **부트스트랩(bootstrap).** 파일명 접두어는 이미 있는데 태그는 아직 없는 볼트를
  편입시킵니다. 체크박스 트리로 범위를 고르고(볼트 전체·일부 폴더·개별 노트 —
  드래그로 훑어 선택, 검색, 태그 없는 노트만 보기), 드라이런으로 미리 보고,
  일시정지 / 재개 / 취소로 진행을 지켜보며, 한 번에 되돌립니다. 문제가 있는
  노트는 실행을 멈추는 대신 건너뛰고 목록에 남깁니다. 접두어는 글자/숫자 경계로
  나눕니다(`S88B07` → `S/88/B/07`, `PROJ123` → `PROJ/123`) — 특정 명명 규칙에
  묶이지 않습니다.
- **중복 정리.** 한 노트에 같은 네임스페이스의 위치 태그가 둘 이상 붙으면
  Trellis가 찾아내 어느 쪽을 남길지 고르게 합니다. 큰 볼트에서도 배치로
  처리하며, 되돌리기를 지원합니다.
- **안전한 파일명 형식 변경.** 슬롯 경계 기호, 기호 양옆 공백(없음 / 왼쪽 /
  오른쪽 / 양쪽), 태그키 내부의 계층 표시(숨김 / `.` / `-` / `_`)를 고릅니다.
  바뀔 파일명을 전부 미리 보여주고 Obsidian의 링크 안전 이름변경으로 적용하며,
  취소나 한 건의 실패가 생기면 적용분을 롤백합니다. 성공 뒤 한 번 되돌리기도
  유지합니다.
- **한국어 / 영어 UI**, Obsidian 언어를 따릅니다.

위 기능은 기본적으로 단일 키 경로로 동작합니다. 두 가지는 선택 기능입니다 —
아래 [고급](#고급)을 보세요.

## 설치

**Obsidian에서:** 설정 → 커뮤니티 플러그인 → 탐색에서 *Trellis*를 검색해 설치하고
활성화합니다.

**수동으로:** [최신 릴리스](../../releases)에서 `main.js`, `manifest.json`,
`styles.css`를 받아 `내-볼트/.obsidian/plugins/trellis/`에 넣고, 설정 →
커뮤니티 플러그인에서 활성화합니다.

## 사용법

- **노트에 태그 달기** — 프론트매터에 위치 태그를 넣으면(`tags: [trel/S88/B07]`)
  파일명 접두어가 `S88B07`로 동기화됩니다.
- **단계 옮기기** — 명령 팔레트나 노트 우클릭 메뉴에서 *하위 위치 함께 변경*을
  실행합니다.
- **트리 열기** — 리본 아이콘으로 열고, 헤더나 설정에서 노트/태그 모드를
  전환합니다.
- **그 자리에서 새 노트** — 트리의 한 갈래 아래에 노트를 만듭니다. Trellis가
  다음 세그먼트를 제안해 줄 수 있습니다(고급의 프리셋 참고).
- **기존 볼트 편입** — *기존 파일명 편입*을 실행해 범위를 고르고, 미리보기 후
  적용합니다.
- **중복 정리** — *중복 위치 태그 점검* 을 실행합니다.
- **파일명 형식 변경** — 경계 기호·공백·계층 표시를 정하고, 볼트 전체의 정확한
  변경 목록을 확인한 뒤 적용합니다.

## 고급

이 도구들은 접힌 **실험 기능 — 파일명 확장** 영역 안에 있습니다. 단일 키 엔진이
기본 경로로 유지됩니다.

**멀티 키 슬롯.** 기본적으로 파일명은 태그키 하나 + 제목입니다. 노트에 식별자가
둘 이상 필요하다면 — 예를 들어 프로젝트 코드 *와* 가로지르는 영역 코드 —
*멀티 키 슬롯* 을 켜서 파일명을 슬롯의 정렬된 목록으로 정의합니다. 태그키 슬롯
하나 이상(각자 자기 태그 네임스페이스에서 동기화), 제목 슬롯 하나, 그리고 그
사이의 구분자로요.

```
#trel/AA/01  +  #key2/BB/02      →   AA01-my-note--BB02
두 번째를 #key2/BB/09 로 변경      →   AA01-my-note--BB09   (자동)
```

슬롯 편집기는 변경을 대기시킵니다 — 슬롯 추가·삭제, 네임스페이스, 경계 기호와
공백, 태그 슬롯별 계층 표시를 정해도 **적용**을 누르기 전까지는 바뀌지 않습니다.
적용 전 정확한 이름 변경 목록을 보여줍니다. 비었거나 중복되거나 잘못됐거나
해석이 모호한 조합은 볼트에 닿기 전에 걸러지고, 실행은 실패 시 롤백되며 되돌릴
수 있습니다. 멀티 키가 켜진 동안 트리·부트스트랩·cascade는 첫 번째 태그키
슬롯을 대상으로 동작합니다.

**루트 네임스페이스.** 태그 트리 전체를 하나의 최상위 루트 아래에 두고 싶다면 —
예컨대 전부 `zettel/` 아래로 — 루트 네임스페이스를 켭니다. 태그는
`#zettel/trel/S88/B07`이 되고, 파일명 접두어는 `S88B07` 그대로입니다(루트는
파일명에 영향을 주지 않습니다). 켜거나 바꾸면 기존 태그를 볼트 전체에서
마이그레이션하는데, 확인을 거치고 한 번에 되돌릴 수 있습니다.

**세그먼트 프리셋.** 트리에서 새 노트를 만들 때 Trellis가 다음 세그먼트를 제안해
줄 수 있습니다 — 순번의 다음 번호, 날짜, 제텔카스텐 타임스탬프, 또는 글자/숫자
교대 방식. 슬롯마다 프리셋을 정하되, 언제든 직접 세그먼트를 입력해도 됩니다.

## 스크린샷

**부트스트랩 — 무엇을 편입할지 고르기.** 이미 태그가 있는 노트는 완료로,
태그 없는 노트는 선택 가능하게 표시됩니다(볼트 전체·폴더·개별 노트).

![부트스트랩 대상 선택](screenshots/bootstrap.png)

**Cascade 이름변경 — 하위 트리 통째로 옮기기.** 태그 하나를 바꾸면 그 아래
모든 노트가 파일명·위키링크까지 함께 따라옵니다.

![Cascade 이름변경](screenshots/cascade-rename.png)

**중복 정리 — 노트당 위치 하나.** 노트에 위치 태그가 둘 이상이면 남길 하나를
고르고 나머지는 제거합니다(되돌리기 가능).

![중복 위치 태그 정리](screenshots/dedup.png)

## 설정

![설정 탭](screenshots/settings.png)

- **위치 태그** — 어떤 태그 계열을 원본으로 삼을지(예: `trel`). 적용
  버튼으로 대기·확정.
- **코드와 제목 사이 기호 / 공백** — 자동 생성 코드와 사용자 제목의 경계 기호와 공백.
- **파일명 코드의 계층 표시** — 숨김(기존 `S88B07`) 또는 `.`, `-`, `_` 표시(예:
  `S.88.B.07`).
- **파일명 코드 위치** — 파일명의 접두(앞) 또는 접미(뒤).
- **트리 뷰** — 켬/끔, 그리고 어느 모드(노트/태그)로 열지.
- **사이드바 뷰 이름** — 트리 탭의 사용자 지정 제목(비우면 기본값).
- **트리 정렬** — 태그키·수정 시각·생성 시각 기준.
- **트리 동작** — 새 노트·뷰 전환·현재 노트는 헤더에 두고, 정렬·접기·기존
  파일명 편입·하위 위치 변경·사용 가능한 되돌리기는 **더보기** 메뉴에 모읍니다.
  각 동작은 계속 개별로 숨길 수 있습니다.
- **멀티 키 슬롯** — 기본 꺼짐. 선택형 슬롯 편집기(고급 참고).
- **루트 네임스페이스** — 기본 꺼짐. 선택형 최상위 루트(고급 참고).
- **언어** — 자동 / 한국어 / 영어.
- **관리 노트** — 관리되는 위치 태그를 가진 노트 수와 활성 네임스페이스를
  한눈에 확인하는 읽기 전용 요약.

## 호환성

Obsidian **1.8.7** 이상이 필요합니다. 데스크톱·모바일 모두.

## 내부 구조

파일명은 구분자로 이은 슬롯의 순서 있는 목록입니다 — 기본은 두 슬롯짜리
`[태그키, 제목]` 구조라, 멀티 키 방식이 코어를 다시 쓰지 않고도 늘어납니다.
변환 로직은 `tagkey.ts`(순수 함수·단위 테스트)에 있고, `main.ts`가 Obsidian
접착층입니다. 실시간 동기화는 태그 경로를 그대로 비춥니다. 반대 방향인
부트스트랩은 표시형 계층 구분자를 정확히 되돌리고, 기존 숨김 모드에서는 평평한
접두어를 글자/숫자 경계로 나눕니다. 숨김 모드는 같은 문자 종류가 이어지는 구간
안의 경계를 복원하지 못합니다.

## 왜 만들었나

제 볼트는 파일명의 짧은 ID 접두어에 기대고 있습니다 — 노트마다 시스템 안에서의
위치를 나타내는 코드가 붙어 있죠. 그 접두어를 손으로 맞게 유지하는 건 번거롭고
틀리기 쉬웠습니다. 그래서 Trellis가 위치 태그로 그것들을 몰게 했습니다. 노트에
태그를 달면 파일명 접두어가 링크 안전하게 따라옵니다. 안정적이고 예측 가능한
접두어 덕에 볼트를 훑기 쉽고, CLI 도구를 ID로 정확한 파일에 겨눌 수 있습니다.
태그가 유일한 원본이고, 파일명과 위키링크는 알아서 따라옵니다.

## 함께 보기

Trellis는 [everything-in-obsidian](https://github.com/CocaPls/everything-in-obsidian) — CLI형 AI로 옵시디언 볼트를 운영하기 위한 개인용 pluggable 시스템 허브 — 의 식별(identification) 조각입니다. Trellis는 단독으로도 완전히 동작하며, 허브는 이게 어디에 맞물리는지에 대한 선택적 맥락일 뿐입니다.
